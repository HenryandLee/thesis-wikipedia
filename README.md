# Editing the Candidate: Pre-Election Dynamics on Wikipedia

This repository contains data and code for my thesis studying how editing activity on Wikipedia pages for U.S. House candidates changes in the period before federal elections (2008–2024).

Wikipedia is a collaboratively edited encyclopedia where anyone can revise an article at any time. Each edit is logged in a publicly accessible revision history. For pages covering political candidates, this history provides a behavioral record of public information production around election cycles. The thesis examines two questions: (1) whether there is a shared national surge in editing activity as Election Day approaches, and (2) whether this activity is organized around each state's primary calendar or around a single national electoral rhythm.

## Directory Structure

```
scripts/                      Analysis pipeline, numbered in execution order
data/
  raw/
    html_parsed_candidates/   Candidate rosters scraped from Wikipedia (CSV, one per cycle-chamber)
    revisions_html_parsed/    Revision histories fetched from the MediaWiki API (JSON, one per page)
  reference/                  State primary dates, manually verified
  cache/fec/                  FEC Candidate Master files
  processed_html_parsed/      Intermediate datasets produced by scripts 031-032
  analysis/
    panel_weekly.parquet      Main econometric panel (page x cycle x week)
    editor_cycle_*.parquet    Editor portfolio datasets for descriptive analysis
    q1_results/               Figures and tables for Q1 (national election-season pattern)
    q2_results/               Figures and tables for Q2 (locality vs. synchronization)
    eda_results/              Figures for the editor portfolio EDA (Section 4)
draft/
  full_draft_copy.pdf         Redacted version of the thesis manuscript
flowchart.mmd / .png          Pipeline flowchart
environment.yml               Conda environment specification
```

## Reproducing the Results

### Setup

```bash
conda env create -f environment.yml
conda activate thesis
```

### Step 1 — Build candidate rosters

Scrape Wikipedia election summary pages to obtain the list of candidates and their Wikipedia page URLs.

```bash
python scripts/011_build_house_roster_backend.py all   # House, 2008–2024
python scripts/012_build_senate_roster.py all          # Senate, 2008–2024, not used in the writeup
```

Output: `data/raw/html_parsed_candidates/`

### Step 2 — Collect revision histories

Fetch the full revision history for every candidate page from the MediaWiki API. This step contacts Wikipedia's servers and takes several hours.

```bash
python scripts/021_collect_revisions.py
```

Output: `data/raw/revisions_html_parsed/` (one JSON per page)

### Step 3 — Process revision data

Join revision histories with candidate metadata, apply cycle filtering (keeping only revisions from cycles when the candidate was on the ballot), identify bot accounts, and produce analysis-ready datasets.

```bash
python scripts/031_process_data.py
python scripts/032_create_analysis_variations.py
```

Output: `data/processed_html_parsed/`

### Step 4 — Build the econometric panel

Construct the page-by-cycle-by-week panel used in the regression analysis. Applies the post-election washout exclusion, page-creation censoring, zero-fills weeks with no edits, and merges state primary dates.

```bash
python scripts/051_build_panel_dataset.py
```

Output: `data/analysis/panel_weekly.parquet`

### Step 5 — Build editor portfolio datasets

Compute geographic and partisan portfolio metrics for each editor-cycle, used in the descriptive analysis of editor behavior.

```bash
python scripts/060_build_editor_cycle_dataset.py
```

Output: `data/analysis/editor_cycle_*.parquet`

### Step 6 — Run analyses and produce figures

Each script below is self-contained and reads from the panel or editor datasets produced above.

```bash
python scripts/052_q1_descriptive_analysis.py    # Figure 1, Figure 1b, Table 1 (Q1)
python scripts/052c_q1_ip_editing_figure.py      # Appendix Figure C (IP editors)
python scripts/053_q2_regression_analysis.py     # Figure 2, Figure 3, Tables 2–3 (Q2)
```

The EDA figures (Section 4) are produced by the notebook:

```bash
jupyter notebook notebooks/04_event_study_analysis.ipynb
```

All outputs are written to `data/analysis/q1_results/`, `data/analysis/q2_results/`, and `data/analysis/eda_results/`.

## Notes

- The raw revision histories (`data/raw/revisions_html_parsed/`) are not tracked in this repo due to size. They can be regenerated by Step 2.
- FEC Candidate Master files (`data/cache/fec/`) are downloaded automatically on first run of Step 3 and cached locally.
- The primary dates file (`data/reference/state_primary_dates.csv`) was compiled by hand from official state election authority sources and verified against FEC records.
